# Backend «Своя Сказка»

Бэкенд генерации книг. Главный принцип: **клиент всегда получает книгу**, даже если все ИИ-сервисы недоступны.

## Как это работает

```
Форма (create.html)
   │  POST /api/book/generate  → сразу получает jobId
   │  GET  /api/book/:id/status (опрос каждые 2 с)
   ▼
Очередь задач (server/lib/jobs.js)
   ▼
Цепочка провайдеров (server/lib/providers.js)
   Gemini → Groq → OpenRouter → Cerebras → (OpenAI, только если задан ключ)
   ▼  если никто не ответил за 40 с / все в лимите / вернули мусор
Локальный шаблон (js/story-template.js) — мгновенно, без интернета
```

- Упавший провайдер (429, 503, таймаут) «остывает» 30–60 с и пропускается — следующие заказы не тормозят.
- Ответ ИИ проверяется: валидный JSON, 4–12 страниц, русский язык, есть имя ребёнка. Иначе — следующий провайдер.
- Если очередь забита, заказ сразу получает шаблонную книгу.
- Если не отвечает сам сервер, `create.html` собирает книгу локально в браузере тем же шаблоном.
- Готовые книги сохраняются в `server/data/generated/` и удаляются через 7 дней (в них имя и данные ребёнка).

## Запуск

```bash
cd server
npm install
cp .env.example .env   # впишите ключи
npm start
npm test               # проверка отказоустойчивости
```

Проверка: `curl http://localhost:3000/api/health` — покажет подключённые провайдеры и те, что сейчас на паузе.

## Бесплатные ключи

Достаточно одного, но чем больше — тем надёжнее. Ключи только в `server/.env`, на фронтенд они не попадают.

| Провайдер | Где взять | Переменная |
|---|---|---|
| Google Gemini | https://aistudio.google.com/apikey | `GEMINI_API_KEY` |
| Groq | https://console.groq.com/keys | `GROQ_API_KEY` |
| OpenRouter | https://openrouter.ai/keys | `OPENROUTER_API_KEY` |
| Cerebras | https://cloud.cerebras.ai | `CEREBRAS_API_KEY` |

Лимиты бесплатных тарифов и списки моделей у провайдеров меняются — список моделей можно поправить в `.env` (`GROQ_MODELS=...`), недоступные модели пропускаются автоматически.

## API

- `POST /api/book/generate` — тело: `{ name, age, gender, eyes, occasion, habits, friends, cast, style, theme, lesson, sequel, design, tariff: 'big'?, coloring: true?, photos: [dataURL ×1–3] }` → `{ jobId }`
- `GET /api/book/:jobId/status` (и `/result`) — `{ status, ready, position, progress, redrawsLeft, canRedraw, result: { title, pages[], cover, coloring[], answers } | { kind: 'book', book, answers } }`
- `POST /api/book/:jobId/redraw` — `{ index, wish? }` → `{ src, left }`: бесплатная перерисовка одной иллюстрации (до `REDRAW_LIMIT`, по листу персонажа — фото к этому времени уже удалено; неудачная попытка не списывается)
- `POST /api/book/:jobId/edit` — `{ edits: [{ page, text }] }` для «Сказки» или `[{ chapter, block, text }]` для «Большой истории» → `{ applied }`
- `POST /api/generate-background` — служебный прямой вызов Gemini для генерации фонов (не для клиентов)

## Геройские иллюстрации (лицо ребёнка)

`photos` в `POST /api/book/generate` — необязательное поле, до трёх data URL (`data:image/jpeg;base64,...`, до 8 МБ
каждое, jpeg/png/webp; старое одиночное `photo` тоже принимается). Если фото есть и настроен `GEMINI_API_KEY`,
`illustrateBook` из `server/lib/illustrate.js` после готового текста:

1. рисует **лист персонажа** — ребёнок в полный рост в одежде книги и спутники из анкеты (описание одежды `look`
   пишет та же модель, что и текст);
2. рисует **обложку** и **каждую иллюстрацию** книги (ребёнок на всех: в «Сказке» — на всех 8 страницах, в «Большой
   истории» — на всех 8–10 иллюстрациях), передавая фото + лист персонажа, чтобы одежда и питомец совпадали везде;
   по `IMAGE_CONCURRENCY` картинок одновременно, в пределах `SHORT_IMAGE_BUDGET_MS` / `BIG_IMAGE_BUDGET_MS`;
3. если заказана раскраска (`coloring: true`, в «Большой истории» — всегда) — делает контурные версии иллюстраций.

Стилей два: «Акварель» и «3D-мультфильм» (`pickStyleKey`; старые названия вроде «Пластилиновый / 3D» тоже
понимаются, остальные падают на акварель).

- Инструкции по сохранению сходства и правила промпт-инжиниринга (без отрицаний в эмоциях, техника рендера
  вместо формы черт лица и т.д.) зашиты в коде как константы, а не генерируются моделью — чтобы формулировки
  не «плыли» от заказа к заказу.
- Если фото нет, ключа нет или Gemini недоступен/квота исчерпана — просто не рисуем лицо: геройская страница
  остаётся с декоративным фоном, книгу это не ломает (тот же принцип отказоустойчивости, что и у текста).
- Фото хранится только в памяти на время генерации одной задачи и не пишется на диск (см. `server/lib/jobs.js`) —
  в отличие от готовой книги, данные о лице ребёнка нужны ровно один раз. Для перерисовки хранится лист персонажа
  (иллюстрация), клиенту он не отдаётся. Готовая книга хранится `BOOK_TTL_DAYS` (по умолчанию год).
- Чужие бренды и персонажи (Майнкрафт, Супермен и т.п.) запрещены в промптах и отсекаются проверкой текста
  (`brandMentions` в `server/lib/story.js`): такой вариант переписывает следующий провайдер.
- **Проверено вручную (2026-09-22):** при живом бесплатном ключе AI Studio генерация текста работает, а вызов
  image-модели вернул `429 RESOURCE_EXHAUSTED` с `limit: 0` для `gemini-2.5-flash-preview-image` — на этом
  ключе бесплатная квота для image-моделей нулевая (обычная практика Google: image-модели часто доступны
  только с включённым billing, даже если сам расход в итоге копеечный). Прежде чем считать функцию рабочей
  end-to-end, включите billing на аккаунте Google AI Studio или проверьте квоту на `ai.dev/rate-limit`.

## Важно

- Ключи не хранить во фронтенде и не коммитить `.env`.
- Шаблонная книга проще ИИ-версии. Когда подключите платный тариф, сервис сам будет чаще отдавать ИИ-версию — код менять не нужно.

## Тариф «Большая история» (многошаговая генерация)

`POST /api/book/generate` с полем `tariff: "big"` запускает конвейер из `server/lib/bigstory.js`:

1. **План** (1 запрос): название, сквозные мотивы, 6 глав по 6–8 сцен, места 6–8 иллюстраций, фраза «Из записей» для каждой главы.
2. **Главы** (6 запросов, по очереди): каждая получает план, краткое содержание прошлых глав и хвост предыдущей. Иллюстрация вставляется в поток текста
   сразу после нужной сцены (и не между вопросом и ответом на него).
3. **Проверка** каждой главы: русский язык, нет иероглифов и латиницы, объём, повторы фирменных фраз. Замечания «мягкие»
   (короткая, повторы) — лучший вариант принимается после двух попыток; «жёсткие» — берётся другой провайдер.
   Если глава не получилась совсем — она собирается из плана. Если не получился план — книга из локального шаблона.

Ход работы виден в `GET /api/book/:id/status` (поле `progress`). Результат — `result.book` (главы и блоки) для `book-pro.html`.
Лимит заказов: `BIG_RATE_LIMIT_MAX` (по умолчанию 3 за 10 минут с одного IP), таймаут: `BIG_BOOK_TIMEOUT_MS` (по умолчанию 8 минут).

Проверка на сайте: запустить сервер и открыть `create.html?tariff=big`, заполнить анкету — откроется `book-pro.html` с прогрессом.
Дополнительные необязательные поля анкеты для этого тарифа: `interests` (увлечения), `special` (особое место или событие).
