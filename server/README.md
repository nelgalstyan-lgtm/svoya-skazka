# Бэкенд «Героёнок»

Сервер — Cloudflare Worker в папке `worker/` (настройки в `wrangler.jsonc` в корне). Он же отдаёт сайт.
Здесь, в `server/`, — общая логика книги, которую использует Worker, и тесты:

- `lib/story.js` — текст «Сказки» (8 страниц), проверка ответа ИИ, запасной шаблон;
- `lib/bigstory.js` — «Большая история»: план → 6 глав → сборка (шаги отдельно: `writePlan`, `writeChapter`, `assembleBigBook`);
- `lib/providers.js` — цепочка текстовых ИИ с переключением: Gemini → Groq → OpenRouter → Cerebras → OpenAI;
- `lib/illustrate.js` — промпты иллюстраций (сходство с фото, стиль, композиция) и выбор образцов (`imageRequest`);
- `lib/booktext.js` — типографика, записки «Из записей…», оформление по теме и возрасту.

Главный принцип: **клиент всегда получает книгу**. Не ответил ИИ — текст из шаблона (`js/story-template.js`);
не нарисовалась иллюстрация — вторая попытка, потом страница остаётся текстовой.

## Как устроен Worker

```
create.html ── POST /api/book/generate (анкета + фото файлами) ──► api.js: фото и задача → R2, сообщение → очередь
                                                                      │
очередь geroenok-start ──► queue.js ──► Workflow BookWorkflow (book.js), по шагам:
    текст (или план, 6 глав, сборка) → лист персонажа → обложка и сцены по 3 → повтор неудавшихся → готово
book.html ── GET /api/book/:id/status (опрос) ──► превью: обложка + 2 страницы / 1-я глава
```

- Шаги Workflow — потому что на бесплатном тарифе у каждого запуска 10 мс процессора. Картинки OpenAI отдаёт в WebP,
  base64 вырезается из ответа без разбора всего JSON (`worker/bytes.js`): 4–6 мс на картинку вместо 18 мс.
- Через очередь — потому что Workflow, созданный прямо из запроса покупателя, OpenAI видит «из страны покупателя»
  и отказывает заказам из РФ (403 `unsupported_country_region_territory`); из обработчика очереди — нет.
- R2 (`geroenok`): `jobs/<id>.json` — задача и книга (картинки только ссылками), `img/<id>/*.webp` — иллюстрации
  (`GET /api/img/<id>/<файл>`), `photos/<id>/<n>` — фото ребёнка: до оплаты, не дольше 48 ч
  (плюс правило R2 `photos-2d`), удаляются сразу после дорисовки.
- Страховка: книга не готова за 15 мин («Большая история» — за 30) — `/status` отдаёт книгу из шаблона.

## API

- `POST /api/book/generate` — multipart: `answers` (JSON анкеты: `name, age, gender, eyes, occasion, habits, friends, cast, style, theme, interests, special, lesson, sequel, design, tariff: 'big'?, coloring: true?`), `photo` ×1–3 (jpeg/png/webp до 8 МБ), `device` (id браузера для лимита превью). Старый JSON с `photos: [dataURL]` тоже принимается. → `{ jobId }`
- `GET /api/book/:id/status` (и `/result`) — `{ status, ready, progress, paid, finishing, redrawsLeft, canRedraw, result }`; до оплаты `result` — превью.
- `POST /api/book/:id/unlock` — заголовок `x-admin-key` = секрет `ADMIN_KEY`: книга оплачена, дорисовываются остальные иллюстрации и раскраска. Потом это будет делать уведомление ЮKassa.
- `POST /api/book/:id/redraw` — `{ index, wish? }`, после оплаты, до 3 раз, по листу персонажа.
- `POST /api/book/:id/edit` — `{ edits: [{ page, text }] }` или `[{ chapter, block, text }]`, после оплаты.
- `GET /api/img/:id/:file` — иллюстрация (кэш навсегда: имя уникально для каждой версии).
- `GET /api/health` — подключённые ИИ; `?openai=1` — отвечает ли OpenAI на запрос прямо из обработки этого посетителя (бесплатно).

## Запуск и проверка

```bash
cd server && npm test        # тесты логики книги и Worker'а (R2, очередь, Workflow, OpenAI подделаны) — бесплатно
cd .. && npx wrangler dev    # сайт и API на http://localhost:8787 (ключи — в .dev.vars, не в git)
```

Без ключей текст берётся из шаблона, иллюстраций нет — так можно проверить всё, кроме ИИ, бесплатно.
Ключи на проде — секреты Worker'а: `npx wrangler secret put OPENAI_API_KEY` (а также `GEMINI_API_KEY`, `GROQ_API_KEY`,
`OPENROUTER_API_KEY`, `ADMIN_KEY`). Список переменных — `server/.env.example`.

**Тесты с настоящим OpenAI платные** (≈15 ₽ превью, ≈30–40 ₽ дорисовка): только когда без них никак.

## Текст книги

- Ответ ИИ проверяется: валидный JSON, русский язык, есть имя ребёнка, нет латиницы и иероглифов, нет чужих брендов
  (`brandMentions`). Не прошёл — следующий провайдер; упавший провайдер «остывает» 30–60 с.
- «Большая история»: план (6 глав по 6–8 сцен, 8–10 иллюстраций) → главы по очереди (каждая получает план,
  краткое содержание прошлых и хвост предыдущей) → проверка («мягкие» замечания — лучший вариант после двух попыток,
  «жёсткие» — другой провайдер; не вышло совсем — глава из плана; не вышел план — книга из шаблона).
- Модели меняются: списки — в `lib/providers.js` или переменными `GROQ_MODELS=...` и т.п.

## Иллюстрации

- Схема: фото → лист персонажа → обложка и страницы по фото + листу, чтобы одежда и питомец совпадали во всей книге.
- OpenAI `gpt-image-1.5`, среднее качество, WebP; Gemini — запасной (на текущем ключе квота на картинки нулевая).
- Промпты и правила сходства — константы в `lib/illustrate.js` (по `docs/story-prompt-template.md`), а не текст модели.
- Стили: «Акварель» (фирменный) и «3D-мультфильм».
